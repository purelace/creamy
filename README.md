# creamy

Коротко о проекте:
Это движок плагинов на WASM, ключевой особенностю которого является, общение между плагинами
не через линковку и последующий вызов функций, а посредством строго 32-байтных сообщений используя память MultiMemory для их обмена.
1 буфер на вход, 1 буфер на выход. Имеют идентичный размер.
Вообще, линковка и вызовы функций есть, но только 1 функция и только 1 вызов для уведомления плагина.

На данный момент шина работает в одном потоке, все плагины также выполняются последовательно. Никаких атомарных блокировок нет.
Архитектура шины позволяет запускать обработку плагинов в несколько потоков, но это даст буст производительности только если плагинов много и/или они долго выполняют свою работу; в ином случае это ухудшит производительность.

Структура сообщения:
  - 4 байта - заголовок
  - 28 байт - полезная нагрузка
Структура заголовка:
  [dst][group][src][kind]
  - dst - получатель (u8)
  - group - группа сообщения (u8)
  - src - отправитель (u8)
  - kind - номер сообщения (u8)


Подобное  архитектурное решение (использование сообщений) создает одну проблему: а как договариваться какой тип за что отвечает? Почему kind == 1 это, допустим команда на выключение ПК, а не команда логгирования. Я решил это так: XML описание сообщений (см. devkit/creamy-sdk/system.xml для примера).

Данное решение решает эту проблему и открывает нам различные возможности по оптимизации обработки сообщений.
Крайне рекомендуется использовать кодогенератор.
На данный момент набор для разработки плагинов сосредоточен под Rust, но это не значит что другие языки не поддерживаются движком.
Можно спокойно писать плагины под Си и подключать их, но для этого нужно написать отдельный набор разработки:
  - Кодогенератор структур сообщений, а также быстрой и эффективной диспетчеризации сообщений. Крайне рекомендуется. 
  - SDK. Эдакий минимальный набор утилит для разработки. (см. devkit/creamy-sdk). Включает в себя встроенную группу (devkit/creamy-sdk/system.xml), которая нужна для минимальной работоспособности плагина в системе движка.

На данный момент проект близок с первой минимально работоспособной версии:
  - Написана шина сообщений (на 99%) и относительно неплохо оптимизирована.
  - devkit написан на 90%, но уже может использоваться для генерации кода, написания своих xml файлов. Также есть CLI утилита для компиляции все составляющий в один пакет плагина.
  - Движок готов на 50%, готов загрузчик плагинов. Осталась только инициализация плагина, проброс буферов и обработка ошибок плагинов. 

###### Использование
  Документации по использованию пока нет и не будет ближайшее время.

###### Производительность:
  На данный момент тестировалась только скорость шины сообщений. На моем i5-11400F удалось достичть скорости от 30 до 80 нс за сообщение (см. engine/creamy-cbus-driver/benches). Не берусь утверждать что мои бенчмарки идеально верно настроены, а потому, реальные значение могут быть иными.
